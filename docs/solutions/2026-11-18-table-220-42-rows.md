# Table 220.42 data had rows nobody read and a missing dwelling tier (#236)

**Problem:** `data/nec/table-220-42.ts` held five rows. The dwelling row stopped at two tiers (no 25% over 120,000 VA). The hotel, warehouse and store rows didn't match Table 220.42 as remembered, and after #218 nothing read them.

## Approach

1. **Take values from what's already ruled, not from memory.** The PE-ruled Part III walk (`residentialLoad.ts::LIGHTING_DEMAND_TABLE`, #155) already has the three dwelling tiers. The data row now uses the same tiers through a `tiers` list, which replaced the fixed first/remainder shape.
2. **Delete what nobody reads, rather than guessing its values.** The issue listed it as an option. A future row comes from the code book with a pinned test.

## Verification

- `tests/table22042Rows236.test.ts`: 150,000 VA → 51,450 VA (was 54,450); the rows are exactly `dwelling` and `all_others`. It fails on `main`.
- UI guardrails unchanged on three QA projects and a sweep of all 12. Independent verifier.

## Reusable lessons

- **When a data table and a validated implementation disagree, align the table to the implementation the PE ruled on.**
- **Unread rows in a safety table are a trap.** The next caller trusts them. Delete them, or pin them from the book.
